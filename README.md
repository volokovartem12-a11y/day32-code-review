# День 32. Автоматическое AI-ревью кода

Пайплайн на GitHub Actions: при каждом новом PR ассистент получает diff и изменённые файлы,
ищет контекст в документации и коде репозитория (RAG) и публикует комментарий с тремя разделами:
**потенциальные баги**, **архитектурные проблемы**, **рекомендации**.

Модель: **AITunnel, gpt-5.6-luna**. Ключ хранится в секретах GitHub и в файлах не записывается.

## Состав

| Путь | Что делает |
|---|---|
| `.github/workflows/ai-review.yml` | GitHub Action: запуск на PR, ревью, комментарий |
| `review/review.py` | Точка входа: diff → индекс → контекст → модель → `review.md` |
| `review/git_changes.py` | Diff `base...head`, список файлов, пропуски (lock, бинарники, удалённые) |
| `review/code_index.py` | RAG по документации и коду репозитория |
| `review/reviewer.py` | Промпт, вызов модели, Markdown комментария |
| `review/llm.py` | Клиент AITunnel (gpt-5.6-luna), вариант Ollama |
| `docs/` | Правила ревью и архитектура — их тоже индексирует RAG |
| `test_day32.py` | Проверки на имитации: временный git-репозиторий с PR, стаб модели |
| `run.ps1` | Запуск на ПК: проверки или ревью локальной ветки |

## Как подключить к своему репозиторию (GitHub)

1. Скопируйте в репозиторий папки `review/` и файл `.github/workflows/ai-review.yml`, а также `requirements.txt`.
2. В GitHub: Settings → Secrets and variables → Actions → New repository secret. Имя: `AITUNNEL_API_KEY`, значение — ваш ключ.
3. Откройте PR. Через пару минут появится комментарий «Автоматическое AI-ревью».

Если секрета нет, шаг тихо пропускается и комментария не будет.

## Как проверить на ПК без GitHub

```
.\run.ps1 -Mode review -Repo "C:\папка\репозиторий" -Base main -Head feature
```

Ключ спросится скрытым вводом. Результат откроется в Блокноте и сохранится в `output\review.md`.

## Что проверено

На имитации (в песочнице): настоящий `git diff base...head` во временном репозитории, пропуски,
индекс кода и документации, контекст для изменённых файлов, ревью через стаб AITunnel,
CLI (ошибки, пустой PR, отсутствие ключа, dry-run), структура workflow.

Только на вашей стороне: запуск на настоящем PR в GitHub Actions, `gh pr comment`, ответ gpt-5.6-luna,
работа на вашем репозитории.

## Ограничения

- Код ревьюера берётся из того же PR: если PR меняет `review/`, ревью запустит изменённую версию.
  Для критичных проектов копируйте `review/` из базовой ветки.
- PR из форков не ревьюятся: секреты там недоступны.
- Лексический поиск (`--embed local`) находит по словам. Семантический (`--embed ollama`) — только на ПК с Ollama.
- Комментарии приходят новыми при каждом обновлении PR, старые не удаляются.
- Модель может ошибаться. Комментарий содержит предупреждение об этом.
