# Архитектура пайплайна ревью

## Состав

- `.github/workflows/ai-review.yml` — GitHub Action: запускается на открытие и обновление PR.
- `review/review.py` — точка входа: сбор diff, индекс, ревью, запись `review.md`.
- `review/git_changes.py` — diff между базовой веткой и head, список файлов, лимиты и пропуски.
- `review/code_index.py` — RAG по документации и коду репозитория, поиск контекста для файлов PR.
- `review/reviewer.py` — промпт, вызов модели, Markdown комментария.
- `review/llm.py` — клиент AITunnel (gpt-5.6-luna) и вариант Ollama.
- `chunking.py`, `loaders.py`, `embeddings.py`, `index_store.py`, `local_llm.py` — RAG-модули из дней 21–28.

## Поток на PR

1. GitHub запускает Action на событие pull_request.
2. Checkout с полной историей (fetch-depth 0), чтобы был базовый коммит.
3. `review.py` считает `git diff origin/main...HEAD`: файлы, изменённые строки, лимиты 12 КБ на файл и 60 КБ на весь diff.
4. Индекс RAG строится заново по текущей версии репозитория.
5. Для каждого изменённого файла ищутся до трёх фрагментов других файлов и документации.
6. Модель получает diff, список файлов и контекст. Ответ — три раздела: баги, архитектура, рекомендации.
7. Action публикует `review.md` комментарием к PR через `gh pr comment`.

## Что важно знать

- Код ревьюера берётся из того же PR. Если PR меняет `review/`, ревью выполнит уже изменённый код.
  Для критичных проектов запускайте ревьюер из базовой ветки.
- Для PR из форков секреты недоступны, поэтому ревью там не запускается.
- Лексический поиск (`--embed local`) находит по словам. Семантический (`--embed ollama`) работает только локально.
